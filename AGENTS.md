# AGENTS.md

This file preserves the approved Machine Studio documentation format for contributors and coding agents.

## README format contract — user-approved 2026-10-26

- Keep `README.md` in English and retain the top language link to `README.ko.md`; keep the Korean document equivalent in structure, facts, versions, commands and limitations.
- Preserve the approved introduction, badges, language links and Hero placement. Keep this sequence: Try it in 3 steps; What it does; Equipment setup; Process and actions; Capture and inspection; Simulation; Experiments and data; Result analysis; Works with OpenVisionLab; Build from source; Documentation; Development status; Part of OpenVisionLab; Contributing and licensing. Translated headings retain the same roles and order.
- Keep detailed workspace behavior, examples, media captions and provenance in `docs/USER_GUIDE.md`, and preserve version history in `CHANGELOG.md`. Update only the sentences, links and media explanations affected by an approved feature change; do not expand the README back into a development log or create duplicate guides.
- Describe the actual source of the target repository. Public and Dev may have different versions, history, supported behavior and media. Do not copy Dev-only claims or an unavailable private asset into the public README. Preserve the approved Hero already available in that repository: the Dev transfer-cycle GIF and the public Simulation PNG are distinct baselines.
- Preserve explicit Apply, Save and Run actions, numerical mock/virtual-source disclosures, linear-sequence restrictions and production/safety limitations. Use short factual English and Korean; remove unsupported praise, AI-style filler and translation artifacts without changing facts, values, dates, licenses or established product terms.
- Preserve existing approved media. When new media is separately authorized, capture the latest matching build's actual maximized UI at native 100% in an FHD-or-larger monitor working area. Keep readable input, action and result; retain source/build/DPI/size provenance. Do not upscale, fabricate states, add cursor/click effects, or retain unnecessary hover/pressed/focus traces. Make GIFs concise by omitting idle time; disclose any time compression and retain meaningful real selection/ROI/result state.
- After editing, inspect the diff and both languages; check exact-case relative paths, images, anchors, repository/branch badge links, version sources and existing build commands. Render the changed Markdown and inspect media, tables and Korean/English wrapping in relevant wide/compact views. Report any inaccessible renderer or unverified screen separately from source checks; do not bypass access restrictions.
- Obtain explicit user confirmation before changing the format itself: section order or heading structure, Hero/media position, language policy or the established document split. Routine factual updates inside the approved format do not require a new format decision. Preserve other authors' unfinished changes and the existing commit/push/publication authorization boundaries; these rules grant no source, settings, product-version, tag or Release changes.
